# How would you handle scale and error handling?
I would use serverless auto-scaling features like AWS Lambda concurrency limits and retries, and implement centralized logging and alerts for fast error detection and recovery.

# How would you predict the cost?
I would monitor usage patterns, set budgets with cloud provider tools like AWS Budgets, and use cost calculators to estimate based on expected invocations or container runtimes.

# What is more cost predictable, containers or serverless?
Containers are generally more cost predictable because they run on reserved or provisioned infrastructure, while serverless costs can spike unexpectedly with sudden traffic surges.

# Explain several pros and cons that would be deciding factors in plans for expansion.
Pros include easier scaling, faster deployment, and lower upfront costs with serverless. Cons include more complex architecture, and harder debugging across distributed systems.

# What roles do elasticity and pay-for-service play in decision making for planned future growth?
Elasticity ensures the app can handle growth without over-provisioning, while pay-for-service helps control costs by only paying for actual usage, making it easier to grow without initial investments.
